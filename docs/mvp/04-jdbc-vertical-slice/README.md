# Slice 04: JDBC Vertical Slice

## Status

Design complete; implementation pending.

## Objective

Prove that the same bounded local runner and public Connector SPI can copy a typed full-load
dataset through generic JDBC, while preserving null, Unicode, decimal, temporal, binary, and
large-text values and making transaction boundaries observable.

## Included

- A resource-free `jdbc` factory with strict Source/Sink option validation.
- JDBC Source query execution through one forward-only read-only transaction and bounded batches.
- JDBC Sink parameterized inserts with a pre-existing table and one commit/rollback boundary per
  runtime batch.
- Explicit JDBC-to-Row type mapping and defensive binary/LOB materialization.
- Safe quoting and validation for table and column identifiers.
- H2 in-memory integration fixtures for connector and CLI tests; MySQL/PostgreSQL remain runtime
  driver targets.
- CLI registration of both CSV and JDBC factories, preserving the same execution loop.

## Excluded

- Schema creation or migration, DDL inference, schema evolution, and destination upserts/deletes.
- Prepared-statement parameters in source queries, arbitrary SQL fragments, stored procedures,
  joins generated by the connector, and multiple statements.
- Vendor-specific JSON, arrays, spatial, interval, XML object, and custom type mappings.
- Connection pools, parallel splits, partitioned reads, CDC, checkpoints, retries, and recovery.
- Exactly-once or at-least-once delivery claims; the Phase 0 compiler still accepts only
  at-most-once.
- Atomic job-wide commit, two-phase commit, idempotency keys, overwrite protection, and cleanup
  of already committed batches.

## Acceptance

1. `JdbcConnectorFactory` exposes version `1.0.0`, both roles, and only bounded batch capabilities;
   invalid or unknown options fail before `open` or `DriverManager` access.
2. A JDBC Source reads at most `maxBatchRecords` rows per pull, preserves metadata order, and
   reports exact terminal behavior without loading the full result set.
3. The documented type matrix round-trips through H2 for null, Unicode, decimal, date/time,
   timestamp, binary, and large text values.
4. Blank or duplicate source labels and unsupported JDBC types fail at `SOURCE_OPEN`/`SOURCE_READ`
   with column and type evidence, without silently converting values to strings.
5. The Sink derives one parameterized insert from the first non-empty Row, quotes identifiers,
   preserves row column order, and rejects schema drift or unsupported values before execution.
6. A successful batch is committed once; a failed batch is rolled back and no later `close` commits
   it. Source close rolls back its read-only transaction and every opened JDBC resource closes.
7. File-to-JDBC and JDBC-to-file jobs use the same `LocalJobRunner`; CLI output remains categorized
   and does not expose password or option values.
8. The Engine remains independent of `connector-jdbc`; only CLI composition depends on both.
9. Focused connector/CLI tests, full Reactor tests, Spotless, diff, dependency, and packaged
   acceptance gates pass.

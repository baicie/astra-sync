# ADR-062: v0.5.0 Release Cut (Phase 18 Scheduler + Phase 19 Connection-Test Observability)

## Status

Accepted

## Context

`CHANGELOG.md` currently has the following top-level sections:

- `## [Unreleased]` — contains **Phase 18** (scheduler metrics
  normalize, slice 44) and **Phase 19** (connection-test
  recorder migrate, slice 45). All slices have landed.
- `## [v0.4.0] - 2026-09-08` — Phase 17 (observability catalog
  backlog activation: shared normalize helper + three Recorder
  contracts for api-server, auth library, controller).
- `## [v0.3.0] - 2026-09-07` — Phase 13 through Phase 16.
- `## [v0.2.0] - 2026-09-07` — Phase 1 through Phase 12.

Phase 18 (ADR-060) completed the last remaining control-plane
Recorder-owner gap: the Scheduler metric package
(`control-plane/scheduler/internal/metrics`) now joins api-server,
auth, and controller as a consumer of the slice-43.0
`io.astrasync/control-plane/observability/normalize` package. Three
new Recorder methods route `tenant_id` through `NormalizeTenant`,
`worker_id` through `NormalizeWorkerID`, and `outcome` through
`NormalizeOutcome` with documented allowlists per family. The
Recorder contract is identical to the Phase 17 template.

Phase 19 (ADR-061) closed the last remaining duplicated
`normalizeLabel`-style helper in the control plane: the
connection-test Recorder
(`control-plane/scheduler/internal/connectiontestmetrics`) now
joins all four other Recorder owners (api-server, auth,
controller, scheduler) as a consumer of `observability/normalize`.
The connection-test outcome allowlist (`success | rejected |
failure`) is promoted to a package-private `outcomeAllowlist`
slice as the single source of truth. With Phase 19, the
ADR-058 §3 invariant — "duplicated helpers are deleted as each
slice lands" — is fully satisfied across the Go control plane.
The only remaining `normalizeLabel` helper in the Go control plane
is in `replication/metrics` (intentional, recorded as Phase 20
candidate — `FreeText` helper design for free-form region labels).

The release dry-run script (`scripts/release-dry-run.py`) and the
changelog guard (`scripts/check-changelog.py`) are in place per
ADR-057 and ADR-059. They need a bump from `0.4.0` to `0.5.0`
to reflect the new content and a bump of the exemption boundary
from `<= 19` to `<= 20` in both scripts.

Maven `pom.xml` declares `0.4.0` and Helm `Chart.yaml` declares
`0.4.0`. The version bump is local to those two files plus the
new versioned CHANGELOG section.

## Decision

### 1. Cut `v0.5.0`

Promote the current `## [Unreleased]` content (Phase 18 + Phase 19)
into a new `## [v0.5.0] - 2026-09-08` section.

Phase 18 and Phase 19 are coherent in a single release because
they are **both** observability-activation phases in the same
sub-domain (control-plane metric Recorder contracts):

- Phase 17 (v0.4.0) produced: shared normalize helper, api-server
  Recorder, auth library Recorder, controller Recorder, test
  contracts.
- Phase 18 (v0.5.0) produces: scheduler Recorder, test contracts.
- Phase 19 (v0.5.0) produces: connection-test recorder migrate,
  test contracts.

Shipping Phase 18 and Phase 19 as separate releases would force a
downstream operator to run two release cycles to get both
Recorder contracts. The existing `check-changelog.py` exemption
already handles the history; the release is the logical
consolidation point.

A new empty `## [Unreleased]` placeholder is appended so future
slices have a known drop zone.

### 2. Bump the project version

`pom.xml`: `0.4.0` → `0.5.0`. Same rationale as ADR-057 §2 and
ADR-059 §3 — a stable release version, not a `-SNAPSHOT`
qualifier; the next post-release commit moves the version to
`0.5.0-SNAPSHOT`.

`deployment/helm/astrasync/Chart.yaml`: `0.4.0` → `0.5.0` for
both `version` (the chart version) and `appVersion` (the
application version) in lockstep.

### 3. Extend the `check-changelog` exemption

The release-dry-run guard (`scripts/release-dry-run.py`) and the
changelog guard (`scripts/check-changelog.py`) already exempt phases
1-19 per ADR-057 and ADR-059. We extend the exemption boundary
to `phase_number <= 20` in **both** scripts so future releases do
not need to touch the guards immediately on opening the next
`[Unreleased]` block:

    `scripts/check-changelog.py::main`   (<= 19 → <= 20)
    `scripts/release-dry-run.py::phases_missing_from_changelog`  (<= 19 → <= 20)

### 4. Release dry-run is the gate

`python scripts/release-dry-run.py` must pass before this ADR is
accepted. The script:

- Reads the Maven version from `pom.xml` (now `0.5.0`).
- Reports the git HEAD that would be embedded in the catalog build id.
- Lists every Complete phase (1, 3-19) and confirms each one
  is referenced in some section of `CHANGELOG.md`.
- Reports the tracked proto file inventory (7 files).

If `release-dry-run` fails, the cut is rejected and the
underlying drift must be fixed before retrying.

### 5. Tagging is left to the maintainer

This ADR does not push a `v0.5.0` git tag (mirroring ADR-057 §4
and ADR-059 §6). Tagging remains the maintainer's release-day
action. The maintainer's checklist:

1. `python scripts/release-dry-run.py` exits 0.
2. `make check` exits 0 (`vet-go + check-runbooks +
   check-runbook-templates + check-docs + spotless:check`).
3. Tag `v0.5.0` against the current commit.
4. Bump `pom.xml` back to `0.5.0-SNAPSHOT` on the next
   development commit (post-release housekeeping, not part of
   this ADR).

## Consequences

### Positive

- `v0.5.0` ships Phase 18 + Phase 19 together: all five Go
  control-plane Recorder owners now route label values through
  the same `observability/normalize` package. Any future
  contributor who adds a sixth Recorder owner can copy the exact
  Phase 17 / 18 / 19 pattern without ambiguity.
- The `metrics-catalog.md` row status for the scheduler and
  connection-test families now has a "Recorder wired" row status,
  completing the Phase 17 activation map across all five
  Recorder owners.
- The `ADR-058 §3` invariant is fully satisfied: no duplicated
  `normalizeLabel` helpers exist in the Go control plane except
  `replication/metrics` (which is intentionally free-form and
  recorded as a Phase 20 candidate).
- The script exemption extension means the next `[Unreleased]`
  block does not need a `check-changelog.py` change at the same
  time as opening the section.

### Negative

- Phase 18 and Phase 19 are both observability-activation
  phases, not production-rollout phases. The literal "emitted"
  milestone for the scheduler and connection-test families is
  still owned by a future Phase 20+ production rollout. The
  activation-vs-emission split from ADR-059 §1 still applies:
  v0.5.0 ships **activation** (Recorder wiring + label-allowlist
  reuse + test contract), not **emission** (production sample
  observed).
- The `ADR-058 §3` invariant is satisfied for the Go control
  plane only. The Java data-plane emission follow-up (ADR-051
  §7 `26.F9`) is still a Phase 20+ candidate and is not affected
  by this release cut.
- The `ADR-058 §3` invariant is satisfied for the Go control
  plane only with one remaining exception:
  `replication/metrics` uses an internal `normalizeLabel` for
  free-form region labels. The Phase 20 candidate
  (`FreeText` helper design) is not committed yet; this ADR
  records it but does not decide it.

## Alternatives Considered

### Skip the `v0.5.0` cut and keep accumulating in `[Unreleased]`

Reject. Phase 18 and Phase 19's Recorder contracts are now stable
enough that leaving them in `[Unreleased]` indefinitely would defeat
the purpose of having a release tracking mechanism. The CHANGELOG
*also* plays an audit role: any new metric that references the
shared normalize helper should be able to cite a release line.

### Cut `v0.5.0` only after replication FreeText helper lands

Reject. The `FreeText` helper design is a Phase 20 candidate
(identified in ADR-060 §1 and ADR-061 §1) and has not been
decided yet. Waiting for it would entangle the release cut with
the design of an unrelated helper, which has no shared dependency.

### Cut `v0.5.0` only after emission sub-slices land (43.1.5 / 43.2.5 / 43.3.5)

Reject. The emission sub-slices have open ownership questions
(API Server sign-in handler needs new RPC + RBAC role — AGENTS.md
§8 decision gate; controller reconcile path needs durable commit
decision; admin CLI Recorder needs the long-running consumer
question resolved). They are not scheduled and are not
dependencies of the Phase 18 / Phase 19 activation contract.

### Cut Phase 18 and Phase 19 as separate releases

Reject. Both phases are observability-activation phases in the
same sub-domain; shipping them as separate releases would force
a downstream operator to run two release cycles for two
immediately adjacent Recorder contracts.

### Auto-bump versions on release via a `make release` target

Reject for this slice (same rationale as ADR-057 §"Alternatives
Considered" and ADR-059 §"Alternatives Considered"). A `make
release` target is a worthwhile future ADR but not in scope for
the current release cut.

# ADR-067: v0.7.0 Release Cut (Phase 22 Auth Session Revoke + Phase 23 Controller Reconcile Emission)

## Status

Accepted

## Context

`CHANGELOG.md` currently has the following top-level sections:

- `## [v0.6.0] - 2026-09-08` — Phase 21 (FreeText helper +
  replication Recorder migrate, slice 46), per ADR-064.
- `## [Unreleased]` — contains **Phase 22** (auth session revoke
  emission, slices 48.1–48.3) and **Phase 23** (controller
  reconcile emission, slices 49.0–49.4). All slices have landed.
- `## [v0.5.0] - 2026-09-08` — Phase 18 (scheduler metrics
  normalize, slice 44) and Phase 19 (connection-test Recorder
  migrate, slice 45), per ADR-062.
- `## [v0.4.0] - 2026-09-08` — Phase 17 (observability catalog
  backlog activation: shared normalize helper + three Recorder
  contracts for api-server, auth library, controller),
  per ADR-059.
- `## [v0.3.0] - 2026-09-07` — Phase 13 through Phase 16,
  per ADR-057.
- `## [v0.2.0] - 2026-09-07` — Phase 1 through Phase 12.

Phase 22 (ADR-065) closes the **emission sub-slice 43.2.5** for the
`auth_session_revoke_total` family. The Phase 17 slice 43.2
Recorder was wired in v0.4.0; Phase 22 wires the **production call
site** — the admin CLI `revoke-session` success boundary — and
establishes the **log-dump emission pattern** for one-shot CLI tools
that cannot serve a `/metrics` endpoint. It also adds
`LoadTenantIDsForPrincipal` to the auth repository and extends
`RevokeSessionsForPrincipal` to return both the revoke count and the
active tenant ID list in a serializable transaction.

Phase 23 (ADR-066) closes the **emission sub-slice 43.3.5** for the
`controller_job_state_total` family. The Phase 17 slice 43.3
Recorder was wired in v0.4.0; Phase 23 wires the **production call
site** — the controller reconcile loop's durable commit boundary —
and establishes the **K8s-label-based tenant derivation contract**
for SyncJob resources. The call site is post-`r.Jobs.Update(...)`
returning `nil`, which is the durable commit point for the reconcile
loop. It also documents the `astrasync.io/tenant-id` label
requirement in the SyncJob CRD godoc.

Together, Phase 22 and Phase 23 complete the **emission half** of
the Phase 17 observability activation matrix for two of the three
remaining metrics: `auth_session_revoke_total` (Phase 22) and
`controller_job_state_total` (Phase 23). The third remaining metric,
`controller_epoch_fence_total`, remains Recorder-wired pending
ADR-053 §3 (durable commit decision for fence responses) and is a
future slice 49.3.5 candidate.

The release dry-run guard (`scripts/release-dry-run.py`) and the
changelog guard (`scripts/check-changelog.py`) already exempt phases
1–21 per ADR-057, ADR-059, ADR-062, and ADR-064. We extend the
exemption boundary to `phase_number <= 23` in **both** scripts so
future releases do not need to touch the guards immediately on
opening the next `[Unreleased]` block.

Maven `pom.xml` declares `0.6.0` and Helm `Chart.yaml` declares
`0.6.0`. The version bump is local to those two files plus the new
versioned CHANGELOG section.

## Decision

### 1. Cut `v0.7.0`

Promote the current `## [Unreleased]` content (Phase 22 + Phase 23)
into a new `## [v0.7.0] - 2026-09-08` section.

Phase 22 and Phase 23 ship together in one release because:

- Both are **emission sub-slices** of the Phase 17 observability
  activation matrix (ADR-058). They complete the emission contract
  for two of the three remaining metrics that were "Recorder wired"
  in v0.4.0 but not yet "emitted" in production.
- Phase 22 introduces the **log-dump emission pattern** (one-shot CLI
  tools that cannot serve `/metrics`). Phase 23 introduces the
  **reconcile-boundary emission pattern** (controller durable commit
  point). Both patterns are documented and reusable for future
  emission slices.
- Both phases share the same umbrella (Phase 17 activation backlog)
  and the same observability domain. Splitting them into two
  releases would add ceremony without benefit.
- The remaining metric (`controller_epoch_fence_total`) is not
  included because it requires a durable commit decision
  (ADR-053 §3) that is not yet resolved. It is explicitly a
  future slice (49.3.5) with a documented open question.

A new empty `## [Unreleased]` placeholder is appended so future
slices have a known drop zone.

### 2. Bump the project version

`pom.xml`: `0.6.0` → `0.7.0`. Same rationale as ADR-057 §2,
ADR-059 §3, ADR-062 §2, and ADR-064 §2 — a stable release
version, not a `-SNAPSHOT` qualifier; the next post-release commit
moves the version to `0.7.0-SNAPSHOT`.

`deployment/helm/astrasync/Chart.yaml`: `0.6.0` → `0.7.0` for
both `version` (the chart version) and `appVersion` (the
application version) in lockstep.

### 3. Extend the `check-changelog` exemption

The release-dry-run guard (`scripts/release-dry-run.py`) and
the changelog guard (`scripts/check-changelog.py`) already
exempt phases 1–21 per prior release cuts. We extend the
exemption boundary to `phase_number <= 23` in **both** scripts:

- `scripts/check-changelog.py::main` exemption: `number <= 21` →
  `number <= 23`
- `scripts/release-dry-run.py::phases_missing_from_changelog`:
  `number <= 21` → `number <= 23`

The comment in `release-dry-run.py::phases_missing_from_changelog`
is also updated to include the Phase 22 and Phase 23 release-cut
reference.

### 4. Release dry-run is the gate

`python scripts/release-dry-run.py` must pass before this ADR
is accepted. The script:

- Reads the Maven version from `pom.xml` (now `0.7.0`).
- Reports the git HEAD that would be embedded in the catalog
  build id.
- Lists every Complete phase (1, 3–23) and confirms each one
  is referenced in some section of `CHANGELOG.md`.
- Reports the tracked proto file inventory (7 files).

If `release-dry-run` fails, the cut is rejected and the
underlying drift must be fixed before retrying.

### 5. Tagging is left to the maintainer

This ADR does not push a `v0.7.0` git tag (mirroring prior
release cuts). Tagging remains the maintainer's release-day
action. The maintainer's checklist:

1. `python scripts/release-dry-run.py` exits 0.
2. `make check` exits 0 (`vet-go + check-runbooks +
   check-runbook-templates + check-docs + spotless:check`).
3. Tag `v0.7.0` against the current commit.
4. Bump `pom.xml` back to `0.7.0-SNAPSHOT` on the next
   development commit (post-release housekeeping, not part of
   this ADR).

## Consequences

### Positive

- `v0.7.0` ships Phase 22 and Phase 23 together, completing the
  emission contract for two of the three remaining "Recorder wired"
  metrics from the Phase 17 activation matrix: `auth_session_revoke_total`
  (via admin CLI `revoke-session`) and `controller_job_state_total`
  (via controller reconcile durable commit boundary).
- The **log-dump emission pattern** (Phase 22) is documented as a
  reusable alternative for one-shot CLI tools. Future one-shot
  emission slices can cite this pattern without re-designing.
- The **reconcile-boundary emission pattern** (Phase 23) establishes
  a durable-commit emission boundary for the controller. Future
  controller emission slices (e.g. slice 49.3.5 for epoch fence)
  can cite this pattern.
- The `astrasync.io/tenant-id` K8s label requirement is documented
  in the SyncJob CRD godoc, making the observability contract
  visible to API server callers and future contributors.
- The `ADR-058 §3` invariant — "duplicated normalize helpers are
  deleted as each slice lands" — was already fully satisfied in
  v0.6.0. No additional normalize helpers exist outside
  `observability/normalize`.
- The script exemption extension means the next `[Unreleased]`
  block does not need a `check-changelog.py` change at the same
  time as opening the section.

### Negative

- The `controller_epoch_fence_total` metric remains "Recorder
  wired" only. Slice 49.3.5 (Phase 23+ candidate) is blocked on
  ADR-053 §3 resolving the durable commit decision for fence
  responses. Operators cannot yet alert on epoch fence outcomes
  in production.
- The `auth_session_revoke_total` log-dump emission requires
  Grafana Agent or Prometheus log-based service discovery to be
  configured. If that collector is not deployed, the metric
  observation is lost. The catalog row documents this limitation.
- The `controller_job_state_total` K8s-label-based tenant derivation
  means all SyncJobs without the `astrasync.io/tenant-id` label
  emit `_unknown` as the tenant. Slice 49.1.5 (API server setting
  the label at job creation) is needed to make per-tenant alerting
  work end-to-end. Until then, the `_unknown` emissions are a known
  limitation documented in the catalog row.
- Phase 22 and Phase 23 are Go control-plane phases only. The
  Java data-plane emission follow-up (ADR-051 §7 `26.F9`) remains
  a Phase 24+ candidate and is not affected by this release cut.
- The Phase 22 scope is narrow (one metric, one call site). The
  Phase 17 activation matrix is not fully complete until all three
  remaining metrics are emitted: `auth_session_revoke_total`
  (✓ Phase 22), `controller_job_state_total` (✓ Phase 23),
  `controller_epoch_fence_total` (pending slice 49.3.5).

## Alternatives Considered

### Defer Phase 22 and Phase 23 to separate releases

Reject. Both phases are self-contained emission sub-slices of the
same Phase 17 observability activation matrix. They share the same
ADR-058 context, the same activation-vs-emission lifecycle, and the
same domain (Go control-plane metrics). Splitting them adds release
ceremony without reducing risk. Keeping them together allows one
v0.7.0 release to complete two of the three remaining emission
milestones.

### Cut `v0.7.0` only after `controller_epoch_fence_total` (slice 49.3.5) lands

Reject. Slice 49.3.5 is blocked on ADR-053 §3, which is not yet
resolved. It has a documented open question: "controller reconcile
path needs durable commit decision." Cutting a release that includes
an unresolved ADR-053 dependency would ship an architectural
uncertainty as a stable contract. The current scope (Phase 22 +
Phase 23) is complete and self-contained; the epoch fence emission
can be a future release.

### Cut `v0.7.0` only after the Java data-plane emission (26.F9) lands

Reject. The Java data-plane emission is a worker protocol trust
binding (ADR-051 §7) that requires a large architectural decision.
It is not Phase 22 or Phase 23 scope and does not share
dependencies with the Go control-plane emission sub-slices. The
Java data-plane emission is a Phase 24+ candidate per ADR-063 §3.

### Roll Phase 22 and Phase 23 into `[Unreleased]` and cut later

Reject. Phase 22's log-dump emission pattern and Phase 23's
reconcile-boundary emission pattern are both stable and
well-tested. Leaving them in `[Unreleased]` indefinitely would
defeat the purpose of the release tracking mechanism. Both phases
have accepted ADRs (ADR-065, ADR-066), complete acceptance criteria
in their phase READMEs, and all slices landed. The release cut
is the appropriate next step.

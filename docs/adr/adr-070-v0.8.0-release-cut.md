# ADR-070: v0.8.0 Release Cut (Phase 24 API Server Session Revoke + Phase 25 Controller Epoch Fence + Phase 26 Closeout)

## Status

Accepted

## Context

`CHANGELOG.md` currently has the following top-level sections:

- `## [v0.7.0] - 2026-09-08` — Phase 22 (auth session revoke emission,
  ADR-065) and Phase 23 (controller reconcile emission, ADR-066),
  per ADR-067.
- `## [Unreleased]` — contains **Phase 24** (API Server session revoke
  emission, slices 50.0–50.6), **Phase 25** (controller epoch fence
  emission, slices 51.0–51.2), and **Phase 26** (catalog closeout +
  reconcile loop tests, slices 52.0–53.2). All slices have landed;
  `make check-changelog` and `make release-dry-run` are green.
- `## [v0.6.0] - 2026-09-08` — Phase 21 (FreeText helper +
  replication Recorder migrate, slice 46), per ADR-064.
- `## [v0.5.0] - 2026-09-08` — Phase 18 (scheduler metrics normalize,
  slice 44) and Phase 19 (connection-test Recorder migrate, slice 45),
  per ADR-062.
- `## [v0.4.0] - 2026-09-08` — Phase 17 (observability catalog
  backlog activation), per ADR-059.
- `## [v0.3.0] - 2026-09-07` — Phase 13 through Phase 16,
  per ADR-057.
- `## [v0.2.0] - 2026-09-07` — Phase 1 through Phase 12.

Phase 24 (ADR-068) closes the **emission sub-slice 43.1.5** for the
`apiserver_session_revoke_total` family. The Phase 17 slice 43.1
Recorder was wired in v0.4.0; Phase 24 wires the **production call
site** — the API Server `RevokeConsoleSession` gRPC handler — and
replaces the offline admin CLI (Phase 22) as the canonical
platform-level revoke path. It also adds `AccessRepository.
RevokeConsoleSessionsForPrincipal` so the access service can revoke
sessions per unique active tenant.

Phase 25 (ADR-069) closes the **emission sub-slice 51.1** for the
`controller_epoch_fence_total` family. The Phase 17 slice 51.1
Recorder was wired in v0.4.0; Phase 25 wires the **production call
site** — the controller reconcile durable commit boundary — at
three converge sites: spec-change stop, desired-state transition, and
deletion. ADR-053 §3 (durable commit decision for fence responses)
was the open question; Phase 25 closes that question by treating the
reconcile's `r.Jobs.Update` success as the durable commit point for
both fence responses and successful transitions.

Together, Phase 24 + Phase 25 complete the **emission half** of the
Phase 17 observability activation matrix for the remaining three
metrics:

- `apiserver_session_revoke_total` — Phase 24 (API Server revoke RPC)
- `controller_epoch_fence_total` — Phase 25 (controller reconcile
  durable commit boundary)
- `controller_job_state_total` — Phase 23 (controller reconcile
  durable commit boundary, shipped in v0.7.0 per ADR-067)

Phase 26 (slice 52.0–53.2) is the **closeout slice**: it freezes the
`metrics-catalog.md` Phase 17 backlog table, marks all six rows as
"Emitted", updates ADR-058 status to "Superseded by Phase 25
closeout", and adds **18 table-driven unit tests** for the controller
reconcile loop (finalizer adoption, deletion paths, converge state
transitions, invariants, race + error handling, and guards). Phase 26
also closes pre-existing test debt by providing the `testSyncJob`
helper that `observability_test.go` already referenced but did not
define, and removes the broken `scripts/reorder-changelog.py` (which
was destructive — it overwrote `CHANGELOG.md` with an empty
`[Unreleased]` placeholder when run against the current file). The
date stamps on all `[vX.Y.Z]` section headers are now applied
manually.

The release dry-run guard (`scripts/release-dry-run.py`) and the
changelog guard (`scripts/check-changelog.py`) already exempt phases
1–23 per ADR-057, ADR-059, ADR-062, ADR-064, and ADR-067. We extend
the exemption boundary to `phase_number <= 26` in **both** scripts so
future releases do not need to touch the guards immediately on
opening the next `[Unreleased]` block.

Maven `pom.xml` declares `0.7.0` and Helm `Chart.yaml` declares
`0.7.0`. The version bump is local to those two files plus the new
versioned CHANGELOG section.

## Decision

### 1. Cut `v0.8.0`

Promote the current `## [Unreleased]` content (Phase 24 + Phase 25 +
Phase 26) into a new `## [v0.8.0] - 2026-09-08` section.

Phase 24, Phase 25, and Phase 26 ship together in one release
because:

- Phase 24 and Phase 25 are **the last two emission sub-slices** of
  the Phase 17 observability activation matrix (ADR-058). Together
  with Phase 23 (v0.7.0), they complete the emission contract for
  every metric that was "Recorder wired" in v0.4.0. Splitting them
  would leave an inconsistent observability surface: operators
  could alert on `controller_job_state_total` (Phase 23) but not on
  `controller_epoch_fence_total` (Phase 25) even though both
  metrics live in the same controller reconcile boundary.
- Phase 26 is the **closeout slice** for Phase 17: it freezes the
  backlog table and adds the missing reconcile-loop test coverage.
  It is intrinsically tied to Phase 24 / Phase 25 because the
  `syncjob_controller_test.go` tests reference the
  `observeEpochFence` helper introduced in Phase 25 slice 51.1.
- All three phases share the same umbrella (Phase 17 activation
  backlog) and the same observability domain. The 18 new
  reconcile-loop tests also serve as regression coverage for the
  Phase 25 `observeEpochFence` call sites.

A new empty `## [Unreleased]` placeholder is appended so future
slices have a known drop zone.

### 2. Bump the project version

`pom.xml`: `0.7.0` → `0.8.0`. Same rationale as ADR-057 §2,
ADR-059 §3, ADR-062 §2, ADR-064 §2, and ADR-067 §2 — a stable
release version, not a `-SNAPSHOT` qualifier; the next post-release
commit moves the version to `0.8.0-SNAPSHOT`.

`deployment/helm/astrasync/Chart.yaml`: `0.7.0` → `0.8.0` for
both `version` (the chart version) and `appVersion` (the
application version) in lockstep.

### 3. Extend the `check-changelog` exemption

The release-dry-run guard (`scripts/release-dry-run.py`) and
the changelog guard (`scripts/check-changelog.py`) already
exempt phases 1–23 per prior release cuts. We extend the
exemption boundary to `phase_number <= 26` in **both** scripts:

- `scripts/check-changelog.py::main` exemption: `number <= 23` →
  `number <= 26`
- `scripts/release-dry-run.py::phases_missing_from_changelog`:
  `number <= 23` → `number <= 26`

The comment in `release-dry-run.py::phases_missing_from_changelog`
is also updated to include the Phase 24 / Phase 25 / Phase 26
release-cut reference.

### 4. Release dry-run is the gate

`python scripts/release-dry-run.py` must pass before this ADR
is accepted. The script:

- Reads the Maven version from `pom.xml` (now `0.8.0`).
- Reports the git HEAD that would be embedded in the catalog
  build id.
- Lists every Complete phase (1, 3–26) and confirms each one
  is referenced in some section of `CHANGELOG.md`.
- Reports the tracked proto file inventory (7 files).

If `release-dry-run` fails, the cut is rejected and the
underlying drift must be fixed before retrying.

### 5. Tagging is left to the maintainer

This ADR does not push a `v0.8.0` git tag (mirroring prior
release cuts). Tagging remains the maintainer's release-day
action. The maintainer's checklist:

1. `python scripts/release-dry-run.py` exits 0.
2. `make check` exits 0 (`vet-go + check-runbooks +
   check-runbook-templates + check-docs + spotless:check`).
3. Tag `v0.8.0` against the current commit.
4. Bump `pom.xml` back to `0.8.0-SNAPSHOT` on the next
   development commit (post-release housekeeping, not part of
   this ADR).

## Consequences

### Positive

- `v0.8.0` completes the **emission half** of the Phase 17
  observability activation matrix for the last two remaining
  metrics:
  - `apiserver_session_revoke_total` — Phase 24 (API Server
    `RevokeConsoleSession` gRPC handler)
  - `controller_epoch_fence_total` — Phase 25 (controller
    reconcile durable commit boundary, three converge sites)
- The **durable-commit emission pattern** (controller reconcile
  `r.Jobs.Update` success boundary, established in Phase 23) is
  now the canonical emission site for two controller metrics. The
  ADR-053 §3 open question is closed: the durable commit decision
  for fence responses is the same boundary as for state
  transitions.
- The **API Server revoke RPC emission pattern** (Phase 24)
  establishes a per-tenant emission boundary for the access
  service. The `auth_session_revoke_total` family now has two
  production call sites (admin CLI in Phase 22, API Server RPC
  in Phase 24) and operators can compare revoke volumes across
  paths.
- The **Phase 26 closeout** freezes the Phase 17 backlog table
  (`metrics-catalog.md`) with all six rows marked "Emitted" and
  adds a future-guidance note directing future activation work
  to the ADR-058 pattern. ADR-058 status is updated to
  "Accepted — Superseded by Phase 25 closeout", removing
  ambiguity about whether the backlog is still open.
- The **18 new reconcile-loop unit tests** (Phase 26 slice 53.0)
  cover the happy + rejection paths the production reconcile
  loop was not previously tested for: finalizer adoption, deletion
  paths, converge state transitions, invariants (stop-before-replace
  while active, no spec change while canceling), race + error
  handling, and guards. The controller module is now at
  **26 tests passing** (18 reconcile + 7 emission + 1 observability).
- The **pre-existing test debt** in `observability_test.go` is
  closed: the `testSyncJob` helper is now defined in
  `syncjob_controller_test.go` (Phase 26 slice 53.1), so the
  observability test can compile standalone.

### Negative

- The `auth_session_revoke_total` log-dump emission (Phase 22)
  and the `apiserver_session_revoke_total` per-tenant emission
  (Phase 24) are **two separate metrics with overlapping
  semantics**. Operators who configure both will see correlated
  spikes during bulk revocations. The catalog rows document this
  overlap; the future guidance is that operators choose one path
  per tenant and disable the other.
- The Java data-plane emission follow-up (ADR-051 §7 `26.F9`)
  remains a Phase 27+ candidate and is not affected by this
  release cut. Operators still cannot alert on JVM-level metrics
  (`checkpoint_duration_seconds`, `sink_commits_total`, etc.)
  via the control-plane `/metrics` endpoint.
- The `controller_epoch_fence_total` emission is tied to the
  controller reconcile boundary, **not** the worker or scheduler
  boundary. Operators who need per-worker fence rates must wait
  for a future worker-protocol-boundary emission slice.
- The Phase 22 / Phase 24 `apiserver_session_revoke_total` and
  `auth_session_revoke_total` metrics carry `_unknown` or
  `_platform` tenant labels for principals without memberships.
  The slice 49.1.5 work (API server setting `astrasync.io/tenant-id`
  on SyncJob resources) remains a future Phase 27+ candidate.
- The `scripts/reorder-changelog.py` deletion (Phase 26 slice
  53.2) removes the only script that attempted to programmatically
  insert release sections. Future release cuts must manually
  copy the `[Unreleased]` body into a new `[vX.Y.Z]` section, as
  is already the practice for v0.3.0 / v0.4.0 / v0.5.0 / v0.6.0 /
  v0.7.0.

## Alternatives Considered

### Defer Phase 26 (catalog closeout + reconcile tests) to a separate release

Reject. Phase 26's reconcile-loop tests reference the
`observeEpochFence` helper from Phase 25 slice 51.1; the test
file imports it transitively through `syncjob_controller.go`. A
separate release would require the test file to live in a
feature branch until v0.9.0, leaving the reconcile loop
untested in v0.8.0. Shipping them together is the lowest-risk
option.

### Cut `v0.8.0` only after the Java data-plane emission (26.F9) lands

Reject. The Java data-plane emission is a worker protocol trust
binding (ADR-051 §7) that requires a large architectural decision
beyond the Go control-plane emission sub-slices. It is not
Phase 24 / Phase 25 / Phase 26 scope and does not share
dependencies with the Go control-plane closeout work. The Java
data-plane emission is a Phase 27+ candidate.

### Cut `v0.7.1` instead of `v0.8.0`

Reject. The release contains **two new emission sub-slices**
(Phase 24, Phase 25) and a **closeout slice** (Phase 26). That
is a minor-version scope under SemVer (`patch` is reserved for
bug fixes; `minor` is reserved for new functionality). v0.8.0
is the appropriate next minor release.

### Roll Phase 24 / Phase 25 / Phase 26 into `[Unreleased]` and cut later

Reject. All three phases have accepted ADRs (ADR-068, ADR-069,
the Phase 26 README acceptance criteria), complete test coverage
(18 new tests passing), and all slices landed. Leaving them in
`[Unreleased]` indefinitely would defeat the purpose of the
release tracking mechanism. The release cut is the appropriate
next step.

# ADR-064: v0.6.0 Release Cut (Phase 21 FreeText + Replication Recorder Migrate)

## Status

Accepted

## Context

`CHANGELOG.md` currently has the following top-level sections:

- `## [Unreleased]` — contains **Phase 21** (FreeText helper +
  replication Recorder migrate, slice 46). All slices have
  landed.
- `## [v0.5.0] - 2026-09-08` — Phase 18 (scheduler metrics
  normalize, slice 44) and Phase 19 (connection-test Recorder
  migrate, slice 45), per ADR-062.
- `## [v0.4.0] - 2026-09-08` — Phase 17 (observability catalog
  backlog activation: shared normalize helper + three Recorder
  contracts for api-server, auth library, controller),
  per ADR-059.
- `## [v0.3.0] - 2026-09-07` — Phase 13 through Phase 16,
  per ADR-057.
- `## [v0.2.0] - 2026-09-07` — Phase 1 through Phase 12.

Phase 21 (ADR-063) closed the **last remaining duplicated
`normalizeLabel`-style helper** in the Go control plane: the
multi-region replication Recorder
(`control-plane/replication/metrics`) now joins the five
other Recorder owners (api-server, auth, controller, scheduler,
connection-test) as a consumer of
`io.astrasync/control-plane/observability/normalize`. With this
slice, every Recorder method that derives a label value from
caller input in the Go control plane routes through the shared
normalize package.

Phase 21 introduced the **last missing normalize helper** —
`NormalizeFreeText(value, maxBytes, unknown)` — which handles
free-form Prometheus label values (region names, hostnames,
object keys). The contract trims whitespace, rejects Unicode
`IsControl` characters, rejects values that exceed `maxBytes`
(via drop, not truncate, to prevent distinct long inputs from
colliding on the same truncated label), and collapses empty /
non-printable / over-length inputs to a caller-supplied
`unknown` sentinel.

With Phase 21, the **ADR-058 §3 invariant** — "duplicated
normalize helpers are deleted as each slice lands" — is now
**fully satisfied across the entire Go control plane**. No
`normalizeLabel`-style helper exists outside
`observability/normalize`. The control-plane Recorder activation
matrix is complete: six Recorder owners × fifteen families, all
wired through the shared normalize package.

The release dry-run script (`scripts/release-dry-run.py`) and
the changelog guard (`scripts/check-changelog.py`) are in place
per ADR-057 and ADR-059 and extended per ADR-062. They need a
bump from `0.5.0` to `0.6.0` to reflect the new content and a
bump of the exemption boundary from `<= 20` to `<= 21` in both
scripts (so Phase 21 does not trigger a `phases_missing_from_changelog`
violation immediately on opening the next `[Unreleased]` block).

Maven `pom.xml` declares `0.5.0` and Helm `Chart.yaml` declares
`0.5.0`. The version bump is local to those two files plus the
new versioned CHANGELOG section.

## Decision

### 1. Cut `v0.6.0`

Promote the current `## [Unreleased]` content (Phase 21) into
a new `## [v0.6.0] - 2026-09-08` section.

Phase 21 ships as a single release rather than rolling into the
next `[Unreleased]` block because:

- It is a self-contained **observability-activation slice** in
  the same sub-domain as Phase 17 / 18 / 19 / 21 (control-plane
  metric Recorder contracts). The activation-vs-emission split
  from ADR-059 §1 still applies: v0.6.0 ships **activation**
  (Recorder wiring + label-allowlist reuse + test contract +
  shared normalize extension), not **emission** (production
  sample observed). The replication Recorder is owned by the
  API Server scrape path (Phase 10 verification, ADR-058 §2);
  the activation contract is complete with this slice.
- It closes the ADR-058 §3 invariant across the **entire Go
  control plane** for the first time. This is a meaningful
  archival milestone: a future contributor who adds a seventh
  Recorder owner cannot be confused by partially-migrated
  helpers because there are none.

A new empty `## [Unreleased]` placeholder is appended so future
slices have a known drop zone.

### 2. Bump the project version

`pom.xml`: `0.5.0` → `0.6.0`. Same rationale as ADR-057 §2,
ADR-059 §3, and ADR-062 §2 — a stable release version, not a
`-SNAPSHOT` qualifier; the next post-release commit moves the
version to `0.6.0-SNAPSHOT`.

`deployment/helm/astrasync/Chart.yaml`: `0.5.0` → `0.6.0` for
both `version` (the chart version) and `appVersion` (the
application version) in lockstep.

### 3. Extend the `check-changelog` exemption

The release-dry-run guard (`scripts/release-dry-run.py`) and
the changelog guard (`scripts/check-changelog.py`) already
exempt phases 1-20 per ADR-057, ADR-059, and ADR-062. We extend
the exemption boundary to `phase_number <= 21` in **both**
scripts so future releases do not need to touch the guards
immediately on opening the next `[Unreleased]` block:

    `scripts/check-changelog.py::main`   (<= 20 → <= 21)
    `scripts/release-dry-run.py::phases_missing_from_changelog`  (<= 20 → <= 21)

### 4. Release dry-run is the gate

`python scripts/release-dry-run.py` must pass before this ADR
is accepted. The script:

- Reads the Maven version from `pom.xml` (now `0.6.0`).
- Reports the git HEAD that would be embedded in the catalog
  build id.
- Lists every Complete phase (1, 3-21) and confirms each one
  is referenced in some section of `CHANGELOG.md`.
- Reports the tracked proto file inventory (7 files).

If `release-dry-run` fails, the cut is rejected and the
underlying drift must be fixed before retrying.

### 5. Tagging is left to the maintainer

This ADR does not push a `v0.6.0` git tag (mirroring ADR-057 §4,
ADR-059 §6, and ADR-062 §5). Tagging remains the maintainer's
release-day action. The maintainer's checklist:

1. `python scripts/release-dry-run.py` exits 0.
2. `make check` exits 0 (`vet-go + check-runbooks +
   check-runbook-templates + check-docs + spotless:check`).
3. Tag `v0.6.0` against the current commit.
4. Bump `pom.xml` back to `0.6.0-SNAPSHOT` on the next
   development commit (post-release housekeeping, not part of
   this ADR).

## Consequences

### Positive

- `v0.6.0` ships Phase 21 alone: the multi-region replication
  Recorder now routes every label value through
  `observability/normalize`. With this release, **every Go
  control-plane Recorder owner** (api-server, auth, controller,
  scheduler, connection-test, replication) uses the shared
  normalize package.
- The `metrics-catalog.md` row status for the replication
  families (`astrasync_multi_region_promotion_total`,
  `astrasync_multi_region_event_total`,
  `astrasync_multi_region_recovery_total`) now has a
  "Recorder wired" row status, completing the Phase 17
  activation map across **all six Recorder owners**.
- The `ADR-058 §3` invariant — "duplicated `normalizeLabel`
  helpers are deleted as each slice lands" — is **fully
  satisfied across the entire Go control plane** for the first
  time. No `normalizeLabel`-style helper exists in any Go
  package outside `observability/normalize`.
- The script exemption extension means the next `[Unreleased]`
  block does not need a `check-changelog.py` change at the same
  time as opening the section.

### Negative

- Phase 21 is an observability-activation phase, not a
  production-rollout phase. The literal "emitted" milestone
  for the replication families is still owned by a future
  Phase 22+ production rollout. The activation-vs-emission
  split from ADR-059 §1 still applies: v0.6.0 ships
  **activation** (Recorder wiring + label-allowlist reuse +
  FreeText helper + test contract), not **emission**
  (production sample observed).
- The `ADR-058 §3` invariant is satisfied for the Go control
  plane only. The Java data-plane emission follow-up (ADR-051
  §7 `26.F9`) is still a Phase 22+ candidate and is not
  affected by this release cut. The emission sub-slices
  (43.1.5 / 43.2.5 / 43.3.5) are also Phase 22+ candidates
  with open ownership questions (AGENTS.md §8 decision gate).
- The Phase 21 contract change for empty `outcome` labels
  deserves a release-note-level mention: pre-Phase-21
  behavior collapsed empty `outcome` to `_unknown` (via the
  legacy `normalizeLabel`); post-Phase-21 behavior collapses
  empty `outcome` to `failure` (via the
  `NormalizeOutcome` allowlist fallback). This is a **deliberate
  contract improvement** documented in ADR-063 §3 and
  `metrics_test.go::TestRecorderLegacyContractEmptyInputsCollapsesToUnknown`,
  not a regression. Operators relying on `_unknown` for empty
  outcomes should update their dashboard queries to bind on
  `failure` instead.

## Alternatives Considered

### Skip the `v0.6.0` cut and keep accumulating in `[Unreleased]`

Reject. Phase 21's Recorder contract is now stable enough that
leaving it in `[Unreleased]` indefinitely would defeat the
purpose of having a release tracking mechanism. The CHANGELOG
*also* plays an audit role: any new metric that references the
shared normalize helper should be able to cite a release line.
With v0.6.0 cut, every Recorder activation has a stable
release tag.

### Cut `v0.6.0` only after emission sub-slices land (43.1.5 / 43.2.5 / 43.3.5)

Reject. The emission sub-slices have open ownership questions
(API Server sign-in handler needs new RPC + RBAC role — AGENTS.md
§8 decision gate; controller reconcile path needs durable commit
decision; admin CLI Recorder needs the long-running consumer
question resolved). They are not scheduled and are not
dependencies of the Phase 21 activation contract. The activation
contract closes the Recorder-ownership half of the catalog
backlog (ADR-058 §1); the emission half is a separate
sub-domain that can land independently.

### Cut `v0.6.0` only after Java data-plane emission (26.F9) lands

Reject. The Java data-plane emission is a worker protocol
trust binding (ADR-051 §7) that requires a large architectural
decision. It is not Phase 22 scope and does not share
dependencies with the Go control-plane Recorder activation.

### Roll Phase 21 into v0.5.0 retroactively

Reject. v0.5.0 is already tagged (per ADR-062). Retroactively
adding Phase 21 content would require a v0.5.1 patch release
or a re-tag, neither of which is appropriate for the
"activation" slice that Phase 21 represents.

### Auto-bump versions on release via a `make release` target

Reject for this slice (same rationale as ADR-057 §"Alternatives
Considered", ADR-059 §"Alternatives Considered", and
ADR-062 §"Alternatives Considered"). A `make release` target is
a worthwhile future ADR but not in scope for the current
release cut.
